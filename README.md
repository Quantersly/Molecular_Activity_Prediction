# Molecular Activity Prediction — SMILES-only baseline

Первый воспроизводимый baseline для соревнования [Kaggle Molecular Activity Prediction Hack](https://www.kaggle.com/competitions/molecular-activity-prediction-hack). Цель — `SI VACV`; метрика соревнования — MSE. Внешние данные и дополнительные модели в этом baseline не используются.

## Данные и ограничения использования

Положите предоставленные `train.csv`, `test.csv` и `sample_submit.csv` в `dataset/`. Набор содержит 320 обучающих и 597 тестовых строк. Проверьте правила Kaggle перед отправкой предсказаний и перед публикацией исходных CSV: конкурсные данные исключены из Git через `.gitignore`.

**Запрет утечки признаков:** `CC50_uM` и `IC50_uM_VACV` связаны с целевой величиной и не должны использоваться как признаки или косвенно участвовать в предсказании. Baseline строит признаки исключительно из `SMILES` и использует `SI VACV` только как целевой столбец train.

## Окружение в WSL

В корне проекта из WSL создайте окружение и установите зафиксированные зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В текущем рабочем окружении разработка и запуск выполняются через WSL virtualenv `.venv`. Версии в `requirements.txt` проверены в этом окружении; воспроизводимость на чистой установке и других версиях Python отдельно не проверялась.

## Запуск

```bash
source .venv/bin/activate
python baseline.py
```

По умолчанию читаются файлы из `dataset/`, а проверенный `submission.csv` сохраняется в корне проекта. Альтернативные пути можно указать параметрами `--data-dir` и `--output`.

Скрипт проверяет порядок колонок (`index`, `SI VACV`), количество строк, соответствие индексов test и sample, а также конечность предсказаний. Test обрабатывается в исходном порядке. Невалидный SMILES вызывает ошибку.

## Признаки, модель и валидация

- RDKit Morgan bit fingerprint из SMILES: radius 2, 2048 бит.
- `ExtraTreesRegressor`: 300 деревьев, `min_samples_leaf=2`.
- Единственный случайный holdout: 20%, `random_state=42`; печатается validation MSE.
- После оценки модель обучается заново на всём train и предсказывает test.

Полученный validation MSE в текущем запуске: **17,442,458.107170**. Это оценка на одном случайном разбиении, а не надёжная оценка обобщения: выборка мала, и результат может заметно зависеть от split. Гиперпараметрический поиск не проводился. Значение лидерборда для конкретной отправки следует записывать отдельно; оно не заменяет локальную валидацию и не использовалось для подгонки модели.

## Следующие шаги экспериментов

1. Выполнить одну проверочную отправку на Kaggle после проверки submission и правил конкурса; записать score и дату.
2. Посчитать распределение `SI VACV` (минимум, медиану, квантили, максимум) и MSE простого baseline с константным предсказанием — это поможет интерпретировать масштаб текущей ошибки.
3. Вести короткий журнал запусков: конфигурация, seed, validation score, при наличии Kaggle score и дата. Сравнивать варианты на одинаковом split.
4. Проверять только одну обоснованную гипотезу за раз. Например, log-преобразование цели может помочь при сильной асимметрии, но меняет оптимизируемую метрику; для сравнения нужно получить предсказания обратно в исходной шкале и считать исходный MSE. До проверки дублей и близких аналогов не использовать случайное разбиение как надёжную оценку.
